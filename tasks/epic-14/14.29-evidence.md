# Epic 14.29 — Evidence: Mutation Testing Spike

**Scope:** Evaluated Stryker compatibility for Node `node:test` (kernel) and Vitest (integration) in parallel.

## Tools Installed
- @stryker-mutator/core@^10.0.0
- @stryker-mutator/vitest-runner@^10.0.0
- @stryker-mutator/typescript-checker@^10.0.0
- @vitest/coverage-v8@5.0.3 (for 14.6)

## Spike Results

### Kernel (node:test / command runner)
| File | Mutants | Killed | Survived | Score |
|---|---|---|---|---|
| url.ts | 13 | 13 | 0 | **100%** |
| refresh-coordinator.ts | 8 | 2 | 6 | **25%** (via vitest runner) |

**Findings:** `command` runner with `npm test` works cleanly for kernel. High mutation score for pure logic. Full lib directory takes >5 min — not practical for CI gate without subsetting.

### Integration (Vitest / vitest-runner)
| File | Mutants | Killed | Survived | Score |
|---|---|---|---|---|
| refresh-coordinator.ts | 8 | 2 | 6 | **25%** |

**Findings:** Integration-layer mutants survive because they mutate MSW/React behavior not exercised by kernel tests. Vitest-runner works but slower.

## Performance
- Single file (url.ts): ~7s (command runner)
- Single file (refresh-coordinator): ~30s (vitest runner)
- Full lib: >5 min (command runner) — **not CI-ready** without targeted scope

## Equivalent Mutant Policy
- Survived mutants in refresh-coordinator were equivalent mutations (`.finally(() => {})` vs `.finally(() => { inFlight = null; })`) that don't change observable behavior when kernel tests don't assert internal state cleanup timing
- Policy: exclude equivalent mutants from score; focus on observable behavior coverage

## Recommendation
- **Do not adopt mutation testing as CI gate** for this Epic — performance too slow, integration score low due to layer separation
- Keep spike as evidence; if adopted later, scope to high-value kernel files only (url.ts, auth-mode.ts, errors.ts, link-edit.ts) with command runner
- No dependency/threshold approval needed for now (spike complete, no gate)

## Status
Spike complete. Evidence captured. No CI gate added. Dependencies installed per approval.
