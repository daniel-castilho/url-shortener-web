## 14.23 — Bearer E2E Journey (API-level)
- Login via `POST /api/v1/auth/login` (JSON) → extracts `token`
- Shorten via `POST /api/v1/urls` with `Authorization: Bearer <token>` (includes `originalUrl`, `customAlias` `api-e2e-test`)
- List via `GET /api/v1/urls` with Bearer token
- Explicit assertions: token obtained, API returns 2xx, responses parsed successfully

**Verification command (local):**
```bash
API_BASE_URL=http://localhost:8080
TOKEN=$(curl -sS -X POST $API_BASE_URL/api/v1/auth/login -H "Content-Type: application/json" \
  -d '{"email":"admin@example.com","password":"password123"}' | python3 -c 'import sys,json;print(json.load(sys.stdin)["token"])')
curl -sf -H "Authorization: Bearer $TOKEN" -X POST $API_BASE_URL/api/v1/urls \
  -H "Content-Type: application/json" -d '{"originalUrl":"https://e2e.example.com/x"}' | python3 -c 'import sys,json;assert "id" in json.load(sys.stdin)'
curl -sf -H "Authorization: Bearer $TOKEN" $API_BASE_URL/api/v1/urls | python3 -c 'import sys,json;d=json.load(sys.stdin);assert "items" in d'
```

## 14.24 — Cookie E2E Journey (API-level)
- Login with `-c cookie_jar` (sets `access_token`/`refresh_token` cookies per backend contract)
- Shorten via `POST /api/v1/urls` with `-b cookie_jar` (no `Authorization` header) → validates cookie auth
- Refresh via `POST /api/v1/auth/refresh` with cookie jar → validates refresh flow
- Explicit assertions: cookies accepted, refresh returns valid tokens/session, 2xx responses

**Verification:**
```bash
COOKIE_JAR=$(mktemp)
curl -sS -c "$COOKIE_JAR" -X POST $API_BASE_URL/api/v1/auth/login -H "Content-Type: application/json" \
  -d '{"email":"admin@example.com","password":"password123"}' >/dev/null
curl -sf -b "$COOKIE_JAR" -X POST $API_BASE_URL/api/v1/urls -H "Content-Type: application/json" \
  -d '{"originalUrl":"https://cookie.example.com/y"}' | python3 -c 'import sys,json;assert "id" in json.load(sys.stdin)'
curl -sf -b "$COOKIE_JAR" -X POST $API_BASE_URL/api/v1/auth/refresh' | python3 -c 'import sys,json;data=json.load(sys.stdin);assert "token" in data or "access_token" in data'
```
