| Risk | Current Mitigations | Test Coverage | Status |

## Regression Cases

1. **XSS in error messages** (integration): Error responses with user-controlled content rendered as escaped text; no script execution
2. **javascript: protocol rejection** (kernel): `isValidHttpUrl('javascript:alert(1)')` returns false
3. **No token in console** (code hygiene): No console.log of access/refresh tokens in src/
4. **Query string token safety**: Auth never puts tokens in URLs (per contract & implementation)
5. **Client validation prevents bad requests**: Invalid URL not sent to API

## Findings
- No critical client-side security issues identified
- Token storage in sessionStorage is documented as JS-readable by design; cookie-mode XSS note documented in twelve-factors
- Security posture relies on backend enforcement (contract is law); frontend validates defensively
- No penetration testing of remote hosts performed (out of scope)

## Status
Regression cases mapped and covered by existing tests/kernel checks. No new tests required; existing coverage sufficient. No code changes.
