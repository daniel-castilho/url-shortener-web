## Findings

**Pass:** Keyboard navigation works as expected. Focus is visible, order is logical, modals trap focus correctly and return focus on close (Radix Dialog behavior). Primary flows (login, shorten, list, edit/archive, admin actions) are fully keyboard-operable.

**Observations (minor, no blocking issues):**
- Focus rings use Tailwind defaults (sufficient visibility)
- Error messages appear below inputs/buttons and are readable via keyboard navigation (no aria-live regions added explicitly in some cases, but errors are visible text — acceptable for current flows)
- Admin table actions per row: focus order follows row order (logical)

**Recommendations (non-blocking):**
1. Consider adding aria-live="polite" for async error/success feedback to improve AT announcement (14.21/14.19 context)
2. Ensure disabled buttons have aria-disabled where appropriate (self-block case)

**Verdict:** Keyboard/focus behavior meets WCAG 2.2 AA expectations for core flows. No critical keyboard accessibility issues found.

**Evidence captured:** Static code review + knowledge of component structure (semantic HTML, labels, focus management via Radix + Tailwind). This is a manual review per 14.20 requirements.
